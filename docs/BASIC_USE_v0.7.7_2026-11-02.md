# 守心 v0.7.7 — 基础功能能不能完成（日常使用记录）

> 视角：模拟"第一次接入、不深挖内部实现"地跑一遍基础功能。就当它是外置记忆，记一件事、回头查。
> 实例：`E:/tmp/use/`（端口 3120，全新 data_dir）
> 场景：筹备一场读书会，跨三天记了 6 条，回头查询。

> **前提校正**：本系统的唯一调用方是智能体，终端用户不直接接触本系统。
> 因此本文"用自然语言问"那一段**按设计边界处理，不算缺陷**（智能体不会那样提问，它自己组织关键词）——已从待修清单中移除。
> 其余各条（写入、抽取、待办归属、待办列表噪音、批量写入语义）与调用方是人是程序无关，全部成立，已整理进 `docs/FIX_P1_v0.7.7_2026-11-02.md`。
> 文中出现"我/用户"处，均指"智能体的调用行为"，不影响结论。

---

## 一句话结论

**记东西没问题，查东西得靠关键词。** 写入、抽取、待办管理、联系人画像这些基础能力都能用；但"用嘴问"这个最核心的动作只对了一半——问句里必须带上具体的词（"读书会"、"周静"），想不起来词就什么都查不到。

## 二、不能完成的部分

### 1. 用自然语言问不出来（最影响日常使用）

6 个问句实测：

| 问句 | 结果 |
|---|---|
| 我还有哪些待办？ | **0 条** |
| 最近要做什么？ | **0 条** |
| 我要买几本书？ | **0 条** |
| 读书会要准备什么？ | 6 条 |
| 周静是谁？ | 6 条 |
| 场地的事谈得怎么样？ | 3 条 |

规律一眼可见：**问句里带实体词就能查到，不带就空**。

"我还有哪些待办"被切成 `['还有', '待办']`，库里的待办叫"举办读书会""购买剩余两本书"，词对不上，0 条。"我要买几本书"切成 `['几本书']`，也匹配不到"两本书"。

而这几条问句的答案其实就在库里——待办有 7 条、"已购八本，还差两本"也存着。**只有我主动说对"读书会""周静""场地"这些词，才拿得到答案。**

对一个"忘了才要查"的记忆系统来说，这个短板很致命：我忘了书名、想不起来那个场地叫什么的时候，恰恰是查不出来的时候。

### 2. 按文档新建待办，会存到别人名下

`docs/API.md:322-326` 给的示例是：

```json
{ "title": "整理下季度客户反馈", "deadline": "2026-11-02T23:59:59+08:00", "importance": "high" }
```

照抄这条请求，返回 200 成功，但落库是：

```
owner_id: "default_user"     ← 不是我的 id
```

我用 `user_id=me` 查待办列表，**这条不在里面**。得自己在 body 里补 `"user_id"` 或用 query 传，才能存到自己的桶里。

第一次照文档做的人，会以为待办存丢了。

### 3. 待办列表里混着系统自己编的条目

7 条待办里有 1 条是心跳自动生成的：

```
澄清: 在最后一条对话中，实体"读的书"和"我已经买了八本"的指代对象不明确。
虽然前面提到了"小林"，但最后一条信息没有明确指出"读的书"是小林读的，
还是指代一个群体或事件。此外，实体"两本"的指代对象也存在不确定性……
```

167 字，deadline 11-08，和普通待办混在同一个列表里。我想要的是"我有什么事要做"，结果得先跳过系统的自言自语。

（上一轮试用时也遇到过，同样的问题：同一段分析会生成 2 条，其中一条标题是整段原文。）

## 三、用起来别扭的小地方

| 现象 | 说明 |
|---|---|
| 批量写入部分失败，整体仍报成功 | 6 条里 4 条因"timestamp 超出合理范围"被拒，接口返回 `"success": true, "accepted": 2, "failed": 4`。不看 `items` 里的逐条 error 根本发现不了 |
| 未来时间戳被拒 | 今天 11-02，传 11-03 / 11-04 的对话时间全部拒绝。传历史日期没问题——所以这条只影响"补记未来"，但也说明边界不明显 |
| 相同内容重复提交不去重 | 同一句话提交两次，库里就是两条，`created_at` 都一样。翻记录时会看到重复 |
| 事件描述里出现"合并自" | 重复内容被合并后，描述会变成 `原文\n---\n合并自: 同样的原文`，看着像显示 bug（去重本身是对的，文案丑） |

## 四、如果只想改一处

**让"我还有哪些待办""最近要做什么"这类无实体词的问句能返回东西。**

这是记忆系统最该有的能力。现在的检索是纯关键词匹配，用户得先想起来关键词才能查——而"想不起来"正是用户来找记忆的原因。

可行的方向（供参考，没验证）：

- 问句里没有实体词命中时，退化成"按时间列最近的待办/事件"（现在这类问句直接返回空，其实用户意图很清楚）
- 或者给待办加一层语义兜底：拿整个问句做一次向量检索，而不只是拿切出来的词去 `LIKE`

配套可以顺手做的：把 `POST /api/todos` 的 `owner_id` 缺省从 `default_user` 改成报错（缺 `user_id` 就 400），免得存丢还以为成功了。

## 五、复现方式

```bash
# 启动（独立实例）
sed -e 's|^port = 3000|port = 3120|' \
    -e 's|^data_dir = "./data"|data_dir = "E:/tmp/use/data"|' \
    config.toml > /tmp/use/config.toml
SHOUXIN_CONFIG=/tmp/use/config.toml ./target/release/shouxin-server.exe

# 写入（时间戳用过去日期）
curl -s -X POST http://127.0.0.1:3120/api/memory/batch -H 'Content-Type: application/json' \
 -d '{"user_id":"me","scope":"user","items":[
   {"conversation":"我想办一场读书会，时间定在 11 月 14 号下午两点，地点在城南的纸鸢书店。","timestamp":"2026-11-01 09:10:00"},
   {"conversation":"纸鸢书店的老板娘叫周静，她说场地可以免费借给我。","timestamp":"2026-10-31 14:20:00"},
   {"conversation":"小林说她那天要出差来不了，目前确定能来的有八个人。","timestamp":"2026-11-01 20:05:00"}]}'

# 查：下面两条应当有结果，实测都返回 0 条
curl -s -X POST http://127.0.0.1:3120/api/search/smart -H 'Content-Type: application/json' \
 -d '{"query":"我还有哪些待办？","limit":5,"scope":"user","user_id":"me"}'
curl -s -X POST http://127.0.0.1:3120/api/search/smart -H 'Content-Type: application/json' \
 -d '{"query":"有多少人来？","limit":5,"scope":"user","user_id":"me"}'

# 对照：这条能查到（含实体词"读书会"）
curl -s -X POST http://127.0.0.1:3120/api/search/smart -H 'Content-Type: application/json' \
 -d '{"query":"读书会要准备什么？","limit":5,"scope":"user","user_id":"me"}'

# 新建待办按文档示例（不带 user_id）会落到 default_user
curl -s -X POST http://127.0.0.1:3120/api/todos -H 'Content-Type: application/json' \
 -d '{"title":"整理下季度客户反馈","deadline":"2026-11-05T23:59:59+08:00","importance":"high"}'
curl -s "http://127.0.0.1:3120/api/todos?scope=user&user_id=me&limit=50"   # 查不到上面那条
```
